# ギャル目線リファイナー

## Purpose（目的）

文章の中身はそのままに、**ものの見方と語り口**をギャル目線へ寄せる。

口調だけ変えても、ペルソナ指定は話し方しか変えない。楽しく読めるかどうかは、読み手、キャラの役割、元の内容が残っているかで決まる。だからこのスキルは「目線（どこを見て、どう言い切るか）」を先に変え、語彙は後から必要な分だけ足す。

変換ルール、語彙、強度別の例は `references/gal-viewpoint.md` にある。迷ったとき、`full` を書くとき、長文を書き換えるときは読む。

## Prerequisites（前提）

- 照合スクリプトには `python3`（標準ライブラリのみ）を使う。なくても書き換えはでき、照合を手で行う。
- APIキー、ネットワーク、追加パッケージは不要。

## Available Scripts（同梱スクリプト）

| Script | Purpose | Arguments |
|---|---|---|
| `scripts/check_preservation.py` | 元文と書き換え後を照合し、数値・URL・出典番号・インラインコードの欠落を報告し、元文の留保文を一覧にする | `<元文ファイル> <書き換え後ファイル> [--json]`。終了コード 0=欠落なし、1=要確認、2=入力ファイルを読めない |

## ワークフロー

### 1. 依頼を読む

- 元の文章、想定読者、媒体（SNS、社内チャット、ブログ、スライドなど）、強度を特定する。
- 強度の指定がなければ `medium`。「全開」「ガチギャル」「盛って」なら `full`。仕事の文書・顧客向けなら `light` を提案する。
- 文章がない場合は、対象の文章を求める。

### 2. 変えてはいけないものを先に固める

書き換える前に、次を頭の中（長文ならメモ）で列挙する。

- 数値、日付、固有名詞、URL、出典番号、引用、コード、表のデータ
- 主張と結論
- **留保・限界・注意書き**（「確認できない」「未検証」「ただし」「〜とは限らない」）

ノリを上げると、留保が真っ先に消えやすい。「効果は確認できていない」が「めっちゃ効く」に化けたら失敗。留保はギャル語で言い直してよいが、意味を残す（例：「効くって決まったわけじゃないから、そこは盛らないでおく」）。

### 3. 目線を変える

以下を文章に合う分だけ適用する。全部入れる必要はない。

1. **自分軸で言い切る。** 「〜と言われている」「一般的には」で他人の評価に預けず、書き手が何をいいと思うかを前に出す。「ここ推せる」「うちはこの考え方が好き」のような**書き手の気持ちの表明は、ギャル目線の中心なので足してよい**（`medium` と `full` では少なくとも1か所入れる。`light` の顧客向け文書では、無理に入れなくてよい）。好みは事実ではなく、読み手も意見として読むからだ。足してはいけないのは、元文にない事実、数値からの新しい評価（「あと8件」）、案内・手順のほう。事実の確度も上げない。
2. **読み手を仲間にする。** 上から説明せず、横に並んで話す。褒めるときは「すごい」で終わらせず、助かった行動や工夫を具体的に言う。
3. **否定で終わらせない。** 問題や失敗を書いたら、見方の言い換えで受け止め、元文にある次の行動へつなぐ。失敗を人格の採点にしない（「自分はダメ」→「今回はここが合わなかった」）。元文に次の行動がないとき、新しい案内・提案・手順を本文に足してはいけない。読み手（特に顧客）は本文を書き手の正式な案内として受け取るので、勝手に足した一文が約束や指示になってしまう。足したい提案があれば、本文の外の変更メモに「追加するなら」として書く。
4. **結論から、まっすぐ。** 回りくどい前置き、謙遜、言い訳を削り、言いたいことを先に置く。
5. **前向きを強制しない。** 落ち込み・怒り・休みたい気持ちを「ネガティブだからダメ」と封じない。休む、断る、相談する選択肢を残す。

### 4. 語り口を強度に合わせる

| 強度 | 目線 | 語彙・語尾 | 使う場面 |
|---|---|---|---|
| `light` | 1〜5を適用 | です・ます調は保ちつつ、硬い敬語（いたします、いただけません）を話し言葉の丁寧語へ崩す。ギャル寄りの語（めっちゃ、ちょっと、〜ですよね、ぜひ〜してみてください）を2〜4か所。絵文字なし | 社内文書、顧客向けの柔らかい案内 |
| `medium` | 1〜5を適用 | 「〜じゃん」「めっちゃ」「まじで」などを要所に。段落ごとに1〜2個まで | ブログ、社内チャット、SNS |
| `full` | 1〜5を適用 | ギャル語・感嘆・合いの手を積極的に。絵文字は媒体が許す場合だけ | 企画ネタ、キャラ台詞、遊びの投稿 |

キャラを濃くするほど口調が目立ち、情報が読み取りにくくなる。長文では一律に盛らず、**導入、難しい概念の言い換え、結論**にギャル成分を集め、データや手順の部分は落ち着かせる。表、コード、引用文、出典リストは原則そのまま。

語彙は `references/gal-viewpoint.md` の語彙表から、文脈に合うものを選ぶ。同じ語の連発（「まじ」「えぐい」の毎文登場）は避ける。

### 5. 照合する

元文と書き換え後をファイルにできる場合は、同梱スクリプトで機械的に照合する。チャットで渡された文章を一時ファイルにするときは、`mktemp -d` で作った専用ディレクトリに置く（共有の場所に固定名で置くと、並行する別の作業に上書きされる）。

```bash
python3 scripts/check_preservation.py <元文ファイル> <書き換え後ファイル>
```

数値・URL・出典番号・インラインコードの欠落を報告し、元文で留保・注意書きを含む文を一覧にする。欠落があれば直す（意図的に削った場合は変更メモに書く）。留保の一覧は、書き換え後に**同じ意味**が残っているかを1文ずつ確かめるためのもの。元の言い回しに戻す必要はない（「確認できない」→「まだ言い切れない」で十分）。スクリプトが動かない場合は手で照合し、その旨を書く。

続けて、次の3点を自問する。

1. **キャラを外しても内容が分かるか。** ギャル語を消して読んでも主張・数値・結論が同じか。元文にない事実・案内が増えていないか、元の数値から新しい評価を作っていないか（「あと8件で目標」など）。書き手の好みの表明はこのチェックの対象外。
2. **読み手との距離が縮まったか。** 単に語尾が変わっただけになっていないか。
3. **面白さよりうるささが勝っていないか。** 勝っていたら強度を1段下げる。

加えて、ギャルマインドの誤用になっていないか確認する。

- 「ギャルは全員明るい」「何も悩まない」のようなステレオタイプを書いていないか
- 前向きさを読み手に押しつけていないか
- 気分転換のヒントを、治療や確実な効果のように書いていないか

### 6. 返す

- 書き換え後の文章を最初に出す。
- 長文なら、その後に短い変更メモ（強度、ギャル成分を集めた箇所、意図的に残した留保や削った箇所）を添える。
- 1文・短文の依頼なら書き換え後だけ返す。複数案を求められたら強度違いで3案。
- ファイルが渡された場合は、元ファイルを上書きせず、別名（例：`<元の名前>.gal.md`）で保存する。上書きを頼まれた場合は従う。

## Limitations（制約と、断る・弱める場面）

- 法律、医療、メンタルヘルスの危機、謝罪、弔意、事故報告：ギャル化すると読み手を傷つけたり誤解させたりする。`light` の目線（結論先・具体的な言い方）だけを提案するか、理由を一言添えて断る。
- 実在の特定人物（芸能人、配信者など）の口調の再現：その人の模倣ではなく、一般的なギャル目線で書く。
- 特定の人を下げる、からかう内容：ギャル目線は仲間を大事にする視点なので、悪口のノリには変換しない。
- 照合スクリプトは表記の一致しか見ない。言い換えた数値（「3時間→1.5時間」を「半分」）や、意味の変わった留保は検出できないので、最後は目で確かめる。
- ブランドや読み手に口調が合うかは判断できない。顧客向けでは、硬めに戻す案を変更メモに添える。

## Troubleshooting

| Error / 症状 | Cause | Solution |
|---|---|---|
| スクリプトが終了コード 2 で止まる | 入力ファイルのパスが違う、または UTF-8 で読めない | パスを確かめる。UTF-8 で保存し直す |
| 「消えた数値」に、言い換えただけの数値が出る | 表記替え（4名→4人、5名中4名→4/5）は機械照合では欠落に見える | 意味が同じなら直さず、変更メモに書く |
| 照合結果がおかしい、別の文章の結果が出る | 一時ファイルを共有の場所に固定名で置き、別の作業に上書きされた | `mktemp -d` の専用ディレクトリで照合し直す |
| `python3` がない、スクリプトが失敗する | 実行環境の制約 | 手で照合し、照合できなかったことを返答に明記する |
| 書き換えがうるさい、情報が読み取れない | 強度が媒体や読み手に対して高すぎる | 強度を1段下げ、ギャル成分を導入・言い換え・結論に集める |
